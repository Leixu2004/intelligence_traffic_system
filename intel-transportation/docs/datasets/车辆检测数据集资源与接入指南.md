> 配套输入：《智慧交通车辆检测数据集与视角选择指南.docx》（视角选择 + UA-DETRAC / KITTI / BDD100K / CitySim 四个数据集 + Python/VSCode 开发建议）。

> 链接核验时间：**2026-09-16**；转换脚本位于 `data/datasets/`，已用合成样本端到端验证。

## 0. 结论先行（一页速览）

本项目是**路侧固定机位**的「车辆检测 → 车牌识别 → 违章判定 → 流量预测」系统：

- 车辆检测器现在直接用官方 COCO 版 `yolov8n.pt`（`config.py` 里 `VEHICLE_CLASSES=[2,3,5,7]`），
  没有用路侧交通数据做过微调；
- 跟踪用 YOLO 内置 ByteTrack/BoT-SORT（`core/detector.py::track`），`track_id` 用于流量计数；
- 轨迹/流量数据进入 TimescaleDB 与 LSTM 预测链（`backend/prediction/`）。

因此四个数据集的定位是：

| 数据集 | 视角 | 对本项目的角色 | 落地动作 |
|---|---|---|---|
| **UA-DETRAC** | 路侧固定（中国路口/高速） | **车辆检测器微调主力 + 跟踪计数评测**，同域、含雨雾夜 | 转 YOLO → 微调 `yolov8` → 导出 ONNX → 替换车辆模型 |
| **CitySim** | 无人机俯视 | 高精度**轨迹/流量**与合流·分流·交织安全事件 | 转 60 秒流量 CSV → 进 LSTM 数据链；安全事件喂违章分析 |
| **BDD100K** | 车载前视（天气最全） | **夜间/雨天难例增强**、红绿灯/交通标志扩展 | 抽子集转 YOLO，按比例混入训练（非主力域） |
| **KITTI** | 车载前视 + LiDAR | 仅在未来做**车载/ADAS/多模态**时使用 | Ultralytics 一行命令自动下载训练 |

> 一句话：**固定路侧主线用 UA-DETRAC，轨迹分析用 CitySim，BDD100K 只做增强，KITTI 留给车载扩展。**

## 1. 视角选择（对照本项目）

| 维度 | 固定视角（路侧/监控） | 车载视角（前视/环视） |
|---|---|---|
| 典型场景 | 流量统计、红绿灯违章抓拍、拥堵分析、**本项目全部主业务** | 自动驾驶感知、ADAS、防碰撞 |
| 相机 | 装在灯杆/路口，俯拍或平视，静止 | 装在行驶车辆上，随车体运动 |
| 数据特点 | 多目标跟踪、全局态势、视角稳定 | 强透视变形、动态交互、自车运动 |
| 对应数据集 | **UA-DETRAC**、**CitySim（俯视）** | **KITTI**、**BDD100K** |
| 本项目模块 | `core/detector.py`、`core/violation.py`、流量计数、LSTM | 暂无；未来扩展方向 |

CitySim 虽是无人机而非灯杆，但相机静止、俯视、面向全局交通流，用途上更接近“固定视角”的轨迹/安全分析，
而**不是**用来训练路侧 2D 检测器（俯视外观与路侧平视差异大）。

## 2. 数据集详解与获取

### 2.1 UA-DETRAC ★★★（最匹配，路侧固定）

- **来源**：美国奥尔巴尼大学（University at Albany）联合北京理工大学；北京、天津 24 个真实路口，
  Canon EOS 550D，960×540 @25fps，约 10 小时、100 段视频、14 万+ 帧。
- **规模**：训练 60 段 / 83,791 帧 / 577,899 框；测试 40 段；全集合计约 **121 万**框、8,250 辆车。
- **标注**：每序列一个 XML；含边界框、车辆 ID（可做跟踪）、遮挡/截断、天气（晴/阴/雨/夜间）、比例；
  - v1 XML：四类 *car / bus / van / others*，但**不含每辆车的细分类标签**；
  - **v3 XML：补充六类车型（Sedan/SUV/Van/Taxi/Bus/Truck 等）与 10 种颜色，推荐下载 v3**；
  - 另有 `ignored_region`（忽略区域，训练时不出框）。
- **许可**：CC BY-NC-SA 3.0（署名、非商业、相同方式共享）。
- **获取**：
  - 官网下载页（免费注册登录；旧 `/Data/*.zip` 直链已 301 迁移到学校站点）：
    https://detrac-db.rit.albany.edu/download ，下载 **DETRAC-Train-Images (5.22GB)** 与
    **DETRAC-Train-Annotations-XML-v3**；
  - Kaggle 完整原始镜像（约 11GB，免注册）：https://www.kaggle.com/datasets/bratjay/ua-detrac-orig/data ；
  - Kaggle 轻量 YOLO 子集（5 段、约 17MB，适合先跑通）：
    https://www.kaggle.com/datasets/xyz6674/ua-detrac-custom ；
  - Roboflow Universe 搜 “UA-DETRAC”，导出选 **YOLOv8**：https://universe.roboflow.com ；
  - 论文：https://arxiv.org/abs/1511.04136 。
- **为什么最匹配**：中国道路、路侧固定机位、自带车辆 ID 与天气标签，既能微调检测器，又能评测
  ByteTrack/BoT-SORT 的跟踪与计数，还能补夜间/雨天鲁棒性——与本项目检测、跟踪、流量三条线全部对齐。

### 2.2 CitySim ★★☆（无人机高精度轨迹，申请制）

- **来源**：美国中佛罗里达大学 UCF Smart & Safe Transportation Lab；12 个地点、1140 分钟（约 19 小时）
  无人机视频 @30fps。
- **场景**：高速基本段、**交织段、合流/分流段**、信号/无信号交叉口、环岛；含大量 cut-in/merge/diverge
  高严重度安全事件；提供 SUMO/CARLA 数字孪生底图与信号配时。
- **标注（轨迹 CSV，每行=某车某帧轨迹点）**：`frameNum`、`carId`、车辆中心/车头/车尾、
  旋转框四角点（像素/英尺/美国地点含经纬度）、`speed`(MPH)、`heading`、`course`、`laneId`。
- **许可/获取**：完整数据**申请制**（隐私），用于教学/研究、不可再分发：
  - 仓库与字段 wiki：https://github.com/ozheng1993/UCF-SST-CitySim-Dataset ；
  - 申请表：仓库 `asset/MainPage/Data_Request_Form.pdf`，发送至 **citysim.ucfsst@gmail.com**；
  - 论文：https://arxiv.org/abs/2208.11036 ；冲突识别工具 A.R.C.I.S：https://github.com/ozheng1993/A-R-C-I-S 。
- **在本项目的用途**：把轨迹聚合成 60 秒流量喂给 LSTM（与现有无人机轨迹数据同构）；用合流/分流/冲突
  事件扩展 `core/violation.py` 的安全分析；对接 SUMO/CARLA 做数字孪生。**不用于训练路侧 2D 检测器。**

### 2.3 BDD100K ★★☆（天气/光照最全，车载前视）

- **来源**：UC Berkeley（Berkeley DeepDrive）；约 1100 小时行车视频中抽帧。
- **规模**：检测 10 万张（train 7 万 / val 1 万 / test 2 万），约 9.5GB、约 147 万框；
  10 类：pedestrian、rider、car、truck、bus、train、motorcycle、bicycle、**traffic light、traffic sign**；
  每张图带 weather / timeofday / scene 标签。
- **标注格式**：JSON（`bdd100k_labels_images_{train,val}.json`，目标框为 `box2d{x1,y1,x2,y2}`）。
- **许可**：教育/研究/非营利免费；商业用途需加入 BDD/BAIR Commons。
- **获取**：
  - 官方门户（免费注册）：https://bdd-data.berkeley.edu （选 `100K Images` + `Detection 2020 Labels`）；
  - Internet Archive 免注册镜像：https://archive.org/details/bdd100k ；
  - 已转 YOLO 的 Kaggle 镜像：https://www.kaggle.com/datasets/paulmaxencebaraton/bdd100k-for-yolov5/data ；
  - FiftyOne：https://docs.voxel51.com/dataset_zoo/datasets/bdd100k.html ；论文：https://arxiv.org/abs/1805.04687 。
- **在本项目的用途**：用 `night/rainy` 子集做**难例增强**，提升夜间/雨天检出；用 traffic light/sign 类别
  扩展红绿灯、标志识别。因是车载视角，存在域差，**按一定比例混入**而非替代 UA-DETRAC。

### 2.4 KITTI ★☆☆（车载 + 激光雷达，未来方向）

- **来源**：KIT（卡尔斯鲁厄理工）+ TTIC；德国城市/乡村/高速；含相机 + LiDAR + GPS/IMU。
- **规模**：目标检测 7481 训练图（Ultralytics 切分 5985/1496），2D/3D 框、跟踪等；8 类
  （car/van/truck/pedestrian/person_sitting/cyclist/tram/misc）。
- **许可**：CC BY-NC-SA 3.0。
- **获取/用法**：官网 https://www.cvlibs.net/datasets/kitti/ ；**最省事**是用 Ultralytics 内置 KITTI
  （自动下载转 YOLO）：`yolo train data=kitti.yaml model=yolov8n.pt epochs=50 imgsz=640`，
  文档 https://docs.ultralytics.com/datasets/detect/kitti/ 。
- **在本项目的用途**：当前固定路侧 LPR/违章业务**不直接需要**；仅当未来扩展到车载感知、车路协同、
  视觉+雷达多模态融合时启用。

> 边界提示：以上四个数据集都**不含车牌标注**，提升的是“车辆检测/跟踪/流量”，不提升车牌检测器
> （`models/exp-7.pt`）与 PaddleOCR。若后续要增强车牌环节，可另行评估 CCPD 等车牌数据集，不在本文范围。

## 3. 在本项目中如何使用（可照做的步骤）

转换脚本与清单在 `data/datasets/`（建议用项目虚拟环境 `intel-transportation/.venv`）：

```
data/datasets/
├─ detrac_to_yolo.py          # UA-DETRAC 序列 XML(v1/v3) -> YOLO
├─ bdd_to_yolo.py             # BDD100K JSON -> YOLO（可按天气/时段过滤）
├─ citysim_to_flow.py         # CitySim 轨迹 CSV -> 项目 60 秒流量 CSV
├─ train_vehicle_detector.py  # YOLOv8 微调 + 导出 ONNX + 打印接入配置
└─ README.md                  # 下载地址与快速命令
```

### 3.1 用 UA-DETRAC 微调车辆检测器并替换 yolov8n.pt（主线）

**第 1 步：转换。** 下载并解压图片与 v3 标注后：

```powershell
cd intel-transportation
.\.venv\Scripts\Activate.ps1
python data/datasets/detrac_to_yolo.py `
  --xml-root    D:/datasets/DETRAC/Train-Annotations-XML-v3 `
  --images-root D:/datasets/DETRAC/DETRAC-train-data `
  --out D:/datasets/DETRAC/yolo_detrac `
  --classes project4 --val-ratio 0.1 --link hardlink
```

- 产出 `images/{train,val}`、`labels/{train,val}`、`train.txt/val.txt/dataset.yaml`；
- 图片默认**硬链接**进标准目录（同盘几乎不占额外空间），跨盘/无权限会自动回退为复制；
- 按**序列**切分验证集，避免同段视频相邻帧跨集泄漏；自动跳过 `ignored_region` 与 `out_of_view` 框；
- `--classes`：`project4`(car/van/bus/truck，默认，对齐本项目) / `detrac4` / `vehicle`(单类)。

**第 2 步：微调 + 导出 ONNX。**

```powershell
python data/datasets/train_vehicle_detector.py `
  --data D:/datasets/DETRAC/yolo_detrac/dataset.yaml `
  --weights yolov8n.pt --epochs 80 --imgsz 960 --batch 16 --name vehicle_detrac
```

- 产物：`runs/vehicle_detrac/weights/best.pt` 与 `best.onnx`（opset 18 FP32，对齐
  `docs/deployment/edge_inference.md`）；脚本结束会打印应填的 `VEHICLE_CLASSES`。
- 算力不足可把 `--weights yolov8n.pt`、`--epochs 40`、`--batch 8`；先用 17MB 的 Kaggle 轻量子集跑通。

**第 3 步：接入主流水线（两处改动）。**

1. 让系统加载新权重（二选一，推荐环境变量，不改代码）：
   ```powershell
   $env:YOLO_VEHICLE_MODEL_PATH = "D:\...\runs\vehicle_detrac\weights\best.pt"
   ```
   或在 `config.py` 把 `YOLO_VEHICLE_MODEL_PATH` 默认值改为该路径。
2. 更新类别白名单。`main.py` 用 `if cls_id not in config.VEHICLE_CLASSES: continue` 过滤，
   而新模型不再是 COCO 的 80 类。`project4` 方案下把 `config.py` 的
   `VEHICLE_CLASSES = [2, 3, 5, 7]` 改为：
   ```python
   VEHICLE_CLASSES = [0, 1, 2, 3]   # 新模型 car/van/bus/truck
   ```
   车型中文名由 `main.py::_vehicle_type` 直接从 `model.names` 读取，**无需另改**；
   单类方案（`vehicle`）则填 `[0]`。

**第 4 步：验证（不要跳过）。** 用项目既有边缘工具链做一致性与性能校验：

```powershell
python edge/export_models.py            # 若需重新/多精度导出
python edge/compare_models.py           # .pt 与 .onnx 检测框一致性
python edge/benchmark.py                # CPU/GPU 延迟、FPS
```

随后用真实路侧视频/图片跑 `main.py`，对比微调前后在雨天、夜间、遮挡场景的召回与误检；
mAP/召回应以**人工标注的现场数据**为准，UA-DETRAC 上的指标只代表该域，不能替代现场验收。

> 车牌模型 `models/exp-7.pt` 与 PaddleOCR 链路保持不变；UA-DETRAC 只替换“车辆检测”这一环。

### 3.2 用 CitySim 扩充轨迹/流量，进 LSTM 预测链

申请拿到 CitySim 数据后（每个位置通常是 `Location/Trajectories/*.csv`）：

```powershell
python data/datasets/citysim_to_flow.py `
  --input D:/datasets/CitySim `
  --out data/lstm_sources/processed/citysim `
  --bin-seconds 60 --with-speed
```

- 产出 `citysim_flow_60s.csv` 与 `per_series/<地点>__<片段>_flow_60s.csv`，表头与
  `backend/prediction/data.py` 的**聚合帧契约**完全一致：
  `series_id,bucket_start_seconds,bin_seconds,vehicle_count,entering_vehicle_count,source_file`；
  另生成 `citysim_speed_60s.csv`（平均/最高车速，MPH 已换算 km/h）。
- 口径与项目既有无人机轨迹处理一致：`vehicle_count`=桶内活跃唯一车辆（占用口径），
  `entering_vehicle_count`=首帧进入车辆（流入口径）。连续无人机视频的空桶按**真实 0**保留，
  与收费站“缺采集=缺口”的语义不同。
- 接入训练：把该目录作为新的聚合数据源，按 `backend/prediction/train_lstm.py` 现有的
  多场景 profile 方式注册一个 `citysim` profile（目标列可选 `vehicle_count` 或
  `entering_vehicle_count`），走“整场景留出验证、train-only scaler、无泄漏构窗”的同一套治理；
  训练后导出 ONNX，FastAPI 与大屏按 metadata 自动加载（参考 KDD/多场景 Demo 的既有做法）。
- 安全事件：合流/分流/交织片段可结合 A.R.C.I.S 的冲突思路，为 `core/violation.py` 增加
  换道冲突/急加减速等**安全替代指标**分析；SUMO/CARLA 底图可用于数字孪生复现。
- 数据边界：CitySim 是美国道路、俯视视角、每段仅数分钟，适合扩充多场景 Demo 与验证预处理链，
  **不能替代有授权的现场跨日期数据用于生产 LSTM**（与项目现有结论一致）。

### 3.3 用 BDD100K 做夜间/雨天增强与红绿灯扩展

```powershell
# 夜间+雨天的机动车/两轮车子集
python data/datasets/bdd_to_yolo.py `
  --labels D:/datasets/bdd100k/labels/bdd100k_labels_images_train.json `
  --labels D:/datasets/bdd100k/labels/bdd100k_labels_images_val.json `
  --images-root D:/datasets/bdd100k/images/100k `
  --out D:/datasets/bdd100k/yolo_night_rain `
  --vehicle-only --timeofday night --weather rainy
```

- 去掉 `--timeofday/--weather` 即全量；去掉 `--vehicle-only` 保留官方 10 类（含 traffic light/sign）。
- 建议把夜间/雨天子集按 10%~30% 比例**混入** UA-DETRAC 主数据（合并图片与标签、统一 dataset.yaml 的
  `names` 顺序），以增强恶劣天气鲁棒性；若加入 traffic light/sign，需相应扩展 `config.VEHICLE_CLASSES`
  之外的新类别白名单与后处理逻辑。
- 车载视角域差明显，混入比例不宜过高，并务必用现场路侧图做最终验证。

## 4. 推荐落地路线（由小到大）

1. **跑通（半天）**：下 Kaggle 17MB 的 UA-DETRAC YOLO 子集 → 用 `train_vehicle_detector.py` 微调
   单类/少量 epoch → 导出 ONNX → 改 `YOLO_VEHICLE_MODEL_PATH` 与 `VEHICLE_CLASSES` → 跑通 `main.py`。
2. **主力替换（1–2 天）**：下完整 UA-DETRAC（建议 v3 标注）→ 转 `project4` → 训练 yolov8n/s →
   `edge/compare_models.py + benchmark.py` 校验 → 现场视频对比评估 → 替换车辆检测权重。
3. **天气鲁棒（可选）**：抽 BDD100K 夜间/雨天子集混入，复测恶劣天气召回。
4. **轨迹/安全（拿到 CitySim 授权后）**：转 60 秒流量 → 注册 `citysim` LSTM profile → 训练/导出/联调；
   探索合流分流安全事件与数字孪生。
5. **车载扩展（远期）**：KITTI/多模态，单独立项。

## 7. 常见问题

- **官网下载点不动 / 要登录**：UA-DETRAC 旧直链已迁移，需在官网注册登录；急用可先用 Kaggle 镜像。
- **硬链接失败**：跨盘或无权限时脚本自动回退复制；也可显式 `--link symlink` 或 `--link copy`。
- **类别对不上（检测不到车/车型乱）**：微调后模型类别 id 已变，必须同步改 `config.VEHICLE_CLASSES`；
  以训练结束打印和 `dataset.yaml` 的 `names` 为准。
- **v1 标注没有 van/truck 区分**：v1 XML 不含每车细分类，脚本归到默认类；要细分请下载 **v3** XML。
- **磁盘占用**：UA-DETRAC 图片约 9GB、BDD100K 约 9.5GB；默认硬链接不重复占空间，仍建议预留 20GB+。
- **CitySim 拿不到全量**：完整数据需邮件申请；仓库 wiki/示例可先用于开发转换与分析代码。
