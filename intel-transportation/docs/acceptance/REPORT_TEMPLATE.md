# 项目1验收报告模板

## 验收信息

项目名称：智慧交通车辆检测、车牌识别、数据存储、预测与可视化系统。

验收日期：`YYYY-MM-DD`。

代码版本：填写 Git commit、分支及工作区是否干净。

验收环境：填写操作系统、CPU、内存、GPU、Python、CUDA/TensorRT、Docker、模型哈希和关键依赖版本。

## 自动门禁结果

执行命令：填写 `python -m acceptance.run ...` 的完整命令。

JSON 报告：填写制品路径与 SHA-256。

Markdown 报告：填写制品路径与 SHA-256。

结果汇总：填写 `PASS`、`FAIL`、`BLOCKED`、`NOT_VERIFIED` 数量与进程退出码。任何 `BLOCKED` 或 `NOT_VERIFIED` 都应在后续章节对应到补证计划，不能写成全量通过。

## 功能链路证据

输入样本：填写视频、图片或摄像头标识、授权状态和 SHA-256。

车辆与车牌结果：填写检测数量、车牌真值、识别结果、事件 ID 与截图路径。

消息与存储：填写 Kafka topic、消费偏移、TimescaleDB 记录主键与查询输出路径。

预测与可视化：填写模型版本、预测请求/响应、可视化截图或录屏路径，并说明它们如何与同一次上游输入关联。

异常与降级：填写异常帧、Kafka 不可用、数据库不可用或硬件不可用时的实际行为及日志路径。

## 精度证据

车辆检测：填写验证集名称、许可、样本数、类别分布、划分方式、模型哈希、评估命令和 mAP。门槛为 `mAP > 0.8`。

车牌识别：填写验证集名称、样本数、车牌类型与场景分布、整牌正确数、总数和准确率。门槛为整牌准确率 `>= 95%`。

交通预测：填写测试时段、独立样本数、目标字段、模型与基线指标。门槛为 `R² > 0.85`，并说明数据是否代表现场生产场景。

## 性能证据

基准方法：填写预热次数、正式迭代次数、并发度、输入尺寸、统计口径以及是否包含 I/O、预处理、后处理、消息、数据库、API 和前端渲染。

结果表应至少包含检测延迟、OCR 延迟、数据库读写 P99、API 延迟、大屏首渲和真实端到端延迟。验收门槛分别是 `<20ms`、`<80ms`、读 `<20ms`、写 `<100ms`、`<50ms`、`<1s` 和 `<200ms`。

## 部署证据

记录 Compose 启动命令、镜像摘要、服务健康状态、端口、API 探测、数据库查询、Kafka 消费和大屏访问结果。只执行 `docker compose config` 时，本节状态保持 `NOT_VERIFIED`。

## 未解决项与结论

逐项列出所有 `FAIL`、`BLOCKED` 和 `NOT_VERIFIED`，写明责任人、所需输入、补证命令和计划日期。最终结论只能依据本报告列出的当前证据给出，不引用参考材料中的预设结论。
