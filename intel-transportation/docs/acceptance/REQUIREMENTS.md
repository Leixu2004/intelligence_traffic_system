# 项目1验收要求归纳

## 文档定位

本文件把《20260911项目1验收_全流程联调与提交》和《车辆检测车牌识别全流程联调技术验收文档》中的要求转换为当前工程可执行、可追溯的验收口径。原材料中的代码片段、目录示例、已通过结论和性能数字是参考内容，不是可以直接运行的指令，也不能在缺少当前项目证据时沿用为本项目结论。

项目1的业务链路是车辆检测、车牌识别、时序数据存储、交通流预测和可视化。当前工程允许硬件能力降级为 CPU 与软件回退，但降级运行只能证明软件链可用，不能替代 GPU、TensorRT、INT8、真实摄像头或目标边缘设备的验收结果。

## 功能与接口要求

完整链路应从视频或图像输入开始，经 YOLOv8 车辆检测、车牌 ROI 定位与裁剪、PaddleOCR 识别及格式校验，生成带时间、摄像头、卡口、检测框和置信度的事件。事件进入 Kafka 与 TimescaleDB，预测服务从一致口径的时序流量生成特征并调用 ONNX 模型，最终由 API 和可视化大屏展示实时与预测结果。

验收证据必须证明同一次运行中的上游输入和下游结果可以关联。源码存在、孤立单元测试通过、模型文件可加载或单个接口返回成功，都不足以单独证明“端到端无断点”。有效证据至少应包含输入样本标识、事件标识、数据库记录、预测响应和可视化结果，并记录运行时间与环境。

检测与识别部分需证明视频流可以稳定读取，车辆检测框和 ROI 坐标有效，OCR 可以输出符合车牌规则的结果，异常帧不会导致进程崩溃，关键错误和降级路径有日志。存储、预测与可视化部分需证明 TimescaleDB 写入及超表行为、SQL 聚合、特征维度、ONNX 输入输出契约、API 响应、大屏刷新和地图点位均符合设计。

## 质量要求

工程应采用一致的 Python 格式与静态检查规则，提交前执行预提交门禁。材料要求不存在 P0 级代码问题，测试覆盖率达到 80% 及以上，显式 `TODO` 或 `FIXME` 少于 5 处。代码还应具备清楚的模块边界、必要类型信息、参数化数据库访问、输入校验、异常处理、日志和显式降级。

本工程用 Ruff 统一承载导入排序、常见 PEP 8 问题、未使用代码和高概率缺陷检查；覆盖率由 Coverage.py 统计 `core`、`backend`、`db` 与 `edge`。静态检查工具未安装、覆盖率数据未生成或扫描范围不足时，状态是 `BLOCKED`，不能按通过处理。

## 精度与性能门槛

两份材料存在不同层级的指标。自动门禁采用能够同时满足两份材料的较严格口径：车辆检测独立标注验证集 `mAP > 0.8`，交通流预测独立测试集 `R² > 0.85`，整牌识别准确率不低于 95%，真实端到端延迟小于 200ms。

分段性能门槛为检测模块小于 20ms、单牌 OCR 小于 80ms、数据库读 P99 小于 20ms、数据库写 P99 小于 100ms、预测 API 小于 50ms、可视化首屏渲染小于 1s。基准报告必须说明硬件、操作系统、Python 与运行时版本、模型哈希、样本来源和规模、预热次数、正式迭代次数、并发度以及统计口径。平均值不能替代 P95 或 P99，随机张量的 `InferenceSession.run` 结果不能替代包含解码、前后处理、消息、数据库、API 和渲染的端到端数据。

当前仓库中的中国收费站预测候选模型已有 `R²=0.8644117562` 的独立测试指标，满足课程材料的预测门槛。该数据只代表研究候选数据集，不构成现场生产精度。现有 ONNX CPU 报告和 PT/ONNX 一致性报告可证明制品可加载及两个推理后端输出接近，但没有人工真值，因此不能证明车辆检测 mAP 或整牌识别准确率。

## 部署与提交要求

提交范围应包含完整 Python 源码、数据库建表与查询脚本、车辆/车牌/预测模型、依赖清单、环境变量示例、Dockerfile 与 Compose 编排、可独立执行的部署说明，以及测试报告、截图和性能记录。Docker 静态配置可解析只是第一层检查；“一键启动通过”还需要实际执行 Compose，并证明 TimescaleDB、Kafka、消费者、预测 API 和大屏均处于健康状态。

涉及真实摄像头、GPU、TensorRT 或边缘硬件而设备不可用时，可以用录制视频、CPU ONNX 或离线事件文件验证软件行为。报告必须明确降级范围，相关硬件性能、温度、功耗和长期稳定性保持 `NOT_VERIFIED`，不得由软件模拟结果推断为已通过。

## 状态与判定

`PASS` 表示当前可追溯证据覆盖了验收对象和门槛。`FAIL` 表示已经获得充分证据，且结果没有达到标准。`BLOCKED` 表示检查所需工具、数据集、硬件或关键制品缺失，当前无法作出通过结论。`NOT_VERIFIED` 表示能力或入口存在，但尚未执行与验收范围匹配的运行验证。

质量门禁退出码 `0` 只在全部检查为 `PASS` 时返回；存在 `FAIL` 时返回 `1`；没有 `FAIL` 但存在 `BLOCKED` 或 `NOT_VERIFIED` 时返回 `2`。这一约定保证自动化流水线不会把“尚未发现失败”误解为“已经验收通过”。
